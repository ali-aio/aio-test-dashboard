Test Dashboard — macOS-style design options

Three directions for the same two screens (Overview and Devices), on mock data. References: the AIO Enroll app (macOS System Settings look, coral selection only), the MDM web dashboard (Poppins, airy grey bg, white cards, coral→periwinkle hairline), and native macOS windows (Finder, Activity Monitor). Toggle dark to compare. Pick one and the real app gets rebuilt on its tokens.

A · System Settings closest to Enroll

The Enroll app's language, one to one: translucent source list with glyph icons, grouped inset lists instead of tables where the data is a list, SF 13px, coral used only for the selected item and the one primary button. Everything else is grey and type weight. Feels like a pane of System Settings.

ProsSame muscle memory as Enroll; grouped lists make "needs attention" and bench status read like a settings pane, not a spreadsheet. Very little chrome, nothing competes with the data. Dark mode is already proven in Enroll.
ConsGrouped lists waste vertical space once a list is long; the devices table still has to be a table, so two list styles coexist. The translucent sidebar is a flat tint in a browser (no real vibrancy). Least "dashboard" of the three — fewer charts above the fold.

B · Finder / Activity Monitor

A document window, not a settings pane: unified toolbar with the view switcher, a source list of groups/filters, an alternating-row table that holds the whole fleet, and an inspector on the right for the selected device. Selection is the coral row, like Finder. Most data per pixel.

C · MDM × Mac closest to MDM web

The MDM dashboard's own tokens — light grey page, white cards with a 1px border, Poppins for headings and big numbers, the coral→periwinkle hairline at the top — with Mac controls (segmented control, grouped sidebar, pills). Someone moving between the MDM and this dashboard sees one family.
